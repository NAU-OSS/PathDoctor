# PathDoctor Code of Conduct

## Our Community Values

PathDoctor aims to create a welcoming and constructive open source community where developers with different levels of experience can participate comfortably.

We value:

- Respectful and professional communication
- Patience with beginners and new contributors
- Constructive technical discussion
- Openness to different ideas and approaches
- Collaboration and learning
- Giving credit for the work of others
- Focusing on problems and solutions rather than individuals

People should feel comfortable asking questions, reporting problems, suggesting improvements, and contributing to the project.

## Expected Behavior

Community members are expected to:

- Treat other participants with respect.
- Give feedback in a constructive way.
- Be patient when someone is unfamiliar with a tool, programming language, or development environment.
- Ask questions when something is unclear instead of making negative assumptions.
- Respect different technical opinions and experiences.
- Accept constructive criticism professionally.
- Keep discussions related to the project and its technical goals.
- Help create an environment where new contributors feel welcome.
- Respect the privacy of other community members.

Technical disagreements are normal in an open source project. Contributors should focus on the technical issue and explain their reasoning without attacking the person who suggested a different approach.

## Unacceptable Behavior

The following behavior is not acceptable in the PathDoctor community:

- Harassment, insults, threats, or personal attacks
- Discrimination based on identity, background, experience level, or other personal characteristics
- Intentionally intimidating or humiliating other contributors
- Repeatedly disrupting technical discussions
- Posting offensive or inappropriate content
- Sharing another person's private information without permission
- Deliberately ignoring community guidelines after being asked to stop
- Attacking someone because their contribution contains mistakes
- Using project communication channels for unrelated harassment or spam

Disagreement with a technical idea is acceptable. Disrespectful behavior toward the person proposing the idea is not.

## Reporting Violations

If you experience or observe behavior that violates this Code of Conduct, please report it to the project maintainer.

For ordinary project disagreements or technical concerns, GitHub Issues may be used.

For sensitive Code of Conduct violations, please do **not** create a public GitHub Issue. Contact the project maintainer privately instead.

Reports should include, when possible:

- A description of what happened
- Where the incident occurred
- Relevant links, screenshots, or messages
- Any additional context that may help explain the situation

Reports will be reviewed as privately and fairly as possible. Information about a report should not be shared publicly unless it is necessary to resolve the situation.

## Enforcement Guidelines

The project maintainer is responsible for reviewing reported violations and deciding on an appropriate response.

Depending on the seriousness and frequency of the behavior, actions may include:

1. **Correction**  
   The contributor may be privately informed that their behavior is inappropriate and asked to correct it.

2. **Warning**  
   A formal warning may be given if inappropriate behavior continues or if the violation is more serious.

3. **Temporary restriction**  
   A contributor may temporarily lose the ability to participate in project discussions or contributions.

4. **Permanent removal**  
   Serious or repeated violations may result in permanent removal from the project community.

Enforcement decisions should consider the context of the situation and should focus on protecting a respectful and productive community.

## Scope

This Code of Conduct applies to participation in PathDoctor project spaces, including:

- GitHub Issues
- Pull Requests
- Code reviews
- Discussions
- Documentation contributions
- Other project-related communication

It also applies when someone is representing the PathDoctor project in another public space.

## Our Goal

The purpose of this Code of Conduct is not to prevent disagreement. Open source development often involves different opinions about design, implementation, and project direction.

The goal is to make sure those disagreements remain respectful and productive.

PathDoctor welcomes contributors who want to help improve the project, learn from others, and help other developers solve development environment problems.
